# Changelog

## Unreleased

- Add backward-compatible integer file services 9..12: `file_open` with
  exact binary `r`/`w`/`a` modes, bounded index-zero `file_read_handle` and
  `file_write_handle` returning actual progress, and `file_close_handle`.
  Preserve services 0..8 and opaque file values, share host limits/cleanup,
  reject stale handles without recycling IDs, and publish metadata,
  SmallC lowering instructions and installed CLI/API conformance coverage.
- Implement all nine v1 host services in `cvmrun` using public CWhip byte,
  file, and standard-I/O APIs. Add host capability settings, an open-file
  limit, structured I/O/configuration errors, deterministic cleanup and
  installed CLI/API service tests. `stdin_byte` uses `/dev/stdin` because the
  public SDK has no raw standard-input byte API; see the interpreter guide.
- Add the installable `cvmrun` 1.0.0 package and `cvm-run` CLI with checked
  execution for v1 opcodes, structured validation/runtime diagnostics, bounded
  configurable VM resources, and explicit host-service errors. Add installed
  CLI and in-memory API conformance tests.
- Add standalone CWhip `cvm-as`, with a CVM-owned grammar generated by the
  separately installed cparsegen at build time, named/forward references,
  checked declarations/literals and function-relative labels, depth-derived
  stack metadata, shared-library encoding and structural validation.
- Add the installable `cvmfile` binary-file adapter over public SDK File byte
  APIs with partial-transfer/error handling and deterministic cleanup.
- Add independent complete assembler goldens, installed file reload/validation,
  opcode/service syntax and error coverage; publish canonical service metadata
  in the shared library. Disassembler and SmallC remain out of scope.
- Add the installable CWhip `cvm` 1.0.0 bytecode package with canonical v1
  format/opcode schemas, checked byte readers/writers and instruction/container
  builders, plus initial structural validation and installed-consumer tests.
- Correct the published minimal golden's header section count to seven,
  matching the normative table, directory entries and 183-byte container.
- Separate SDK selection into `cwhip/sdk.toml` so editor/debugger preference
  rewrites cannot erase it. Read legacy `settings.toml` only when the dedicated
  file is absent, consistently in CMake and setup. Keep environment overrides,
  strict validation, and explicit-prefix-only package discovery.
- Retain compatibility with the whole installed SDK prefix from the top-level `sdk_prefix`
  string in `$XDG_CONFIG_HOME/cwhip/settings.toml` (or
  `$HOME/.config/cwhip/settings.toml` when `XDG_CONFIG_HOME` is unset/empty)
  in both CMake and setup when `sdk.toml` is absent.
  Preserve precedence: non-empty `CWHIP_SDK` > SDK config (or legacy settings) > normal CMake
  discovery. Parse TOML with Python 3.11+ without evaluating or modifying
  user settings, and reject invalid selections without falling back.
- Export a settings-selected SDK to the setup shell and add regression
  coverage for discovery precedence, TOML paths, errors, and shell handoff.
- Add the standard MIT license.
- Add a CWhip hello-world starter with a project setup script and interactive
  development shell.
- Configure CMake to discover an installed CWhip 0.0.1 SDK, support explicit
  SDK selection, and place application/native outputs in configurable
  project directories.
- Document SDK selection, building, output customization, and project-shell
  commands.

The starter requires a CWhip SDK that provides configurable application
output directories. SDKs without the `Cwhip_APPLICATION_OUTPUT_DIRECTORIES`
capability are rejected during configuration.
